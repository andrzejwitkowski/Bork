1. Background

The broad picture (skip if you know the compiler)

Bork is a compiled language with arena-based memory: objects live in an arena, and the whole arena is freed at once when its owner dies. The compiler runs source through a parser, a type checker (typeck), a mid-level IR (MIR) and finally LLVM codegen. Its standard library is not special: a handful of prelude chunks written in Bork itself are parsed together with your program, and a chunk is only included when the program names something it defines.

Until now, Vec has been implemented inside the compiler. Issue #285 wants to move collections into Bork itself. That needs a way to say “give me N raw slots and let me read and write them”, which is by nature unsafe: an out-of-range index or a stale pointer is memory corruption.

What this change needs from the existing system

  • A gate in the parser and typeck, so raw slot access exists but only the prelude can reach it.
  • A new opaque type, a fat handle, that codegen can lower to {ptr, i32}.
  • Guards in MIR, so every access is bounds-checked before codegen sees it.
  • A real client: an internal Stack<T> that proves the primitives are enough.

2. Intuition

The design is a vault with two locks and a guard at the inner door.

user source
→ parser lock →
prelude source
→ typeck lock →
primitive call
→ MIR guard →
raw slot access
  1. Parser lock. The keyword unsafe parses only in prelude source. A user who writes unsafe { } or unsafe fun gets `unsafe` is only allowed in the prelude.
  2. Typeck lock. Even in code that parses, slotLoad, slotStore, bufAlloc, bufGrow, abort and arenaOf need an enclosing unsafe. Otherwise: `slotLoad` requires an `unsafe` context.
  3. MIR guard. Lowering inserts the checks, so the access can never be out of range.
Key idea. A Buf<T> is just {ptr, cap}: a pointer and a length. It has no arena header, so it can be copied bitwise. All safety comes from the guards around the primitives, not from the type.

Why newStack goes through StackSeed

bufAlloc needs an arena, and the only source of one is arenaOf(this), which needs a method receiver. newStack is a free function, so it builds a throwaway StackSeed object whose method empty() allocates a zero-byte buffer. The first push then grows it inside the Stack’s own arena.

fun get(i: i32): T {
    unsafe {
        if (i < 0 || i >= this.n) { abort() }   // checks n, not cap
        val b = this.buf
        return slotLoad(&b, i)               // MIR guard checks cap
    }
}

4. Known limits

Stack is an internal prototype. Its public fields let user code copy a Buf out, and bufGrow allocates in the arena of this without checking who owns the buffer, so a handle can dangle. Tracked in #350 (blocks #285 step 2). Also: non-scalar elements #355, Buf<T>? diagnostic #351, Layouts #352, confusing newStack redefinition error #353. The review threads on unsafe_depth were checked: its increment and restore always pair up, since typeck has no early exits.
