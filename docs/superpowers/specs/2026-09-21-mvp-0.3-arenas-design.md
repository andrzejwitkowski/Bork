# Bork MVP 0.3 — Arena Memory Model & Move Semantics

## Goal

Add compile-time region/arena analysis, `move` syntax, CLI `--dump-arenas`, LSP ownership feedback, and a user handbook. LLVM codegen remains out of scope.

## Decisions

| Topic | Choice |
|-------|--------|
| Runtime | Compile-time analysis only; `Arena` is a 4KB bump model for future LLVM |
| `move` syntax | Both `move (a, b) { … }` and trailing `action() move { … }` / `move (caps) { p -> … }` |
| Copy vs Move | Non-null primitives Copy across arenas; named/`Func`/nullable types require `move` |
| Nested braces | Collapse pure brace wrappers; dump annotates compacted count |
| Move invalidation | Mark binding `Moved` (name dead); do not reclaim parent bytes until arena `reset` |
| LSP | Parse + sema diagnostics, hover ownership, `bork.dumpArenas` command |

## Pipeline

Parse → collapse pure nested bare blocks → ownership walk → `ArenaReport` → ASCII dump and/or diagnostics.

## Arena model (future runtime)

- Fixed buffer: 4096 bytes per region
- `alloc`: bump offset; panic if `offset + size > 4096`
- Exit / loop iteration: `reset()` → offset 0 (bulk free)
- Move: relocate value into child arena; parent binding invalidated; dead bytes remain until parent reset

## Non-goals

- LLVM / executing Bork
- Full typechecker beyond the Copy-primitive set
- AST spans (best-effort LSP locations)
- Mid-arena freelist or debug poison
