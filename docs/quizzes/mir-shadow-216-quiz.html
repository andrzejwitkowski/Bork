1. Background

For beginners: what is a compiler pass, and why replace one?

A compiler turns source text into a program through a chain of representations. Between them run passes: small analyses that each decide one thing, such as “may this value outlive its scope?”. Bork keeps its memory in arenas: regions of memory freed all at once when a scope ends. Several passes decide which arena a value goes into and when arenas are pushed, reset and popped.

Today those decisions are spread over several walkers over the high-level tree (HIR). Each re-implements parts of the same rules. RFC 0006 proposes a mid-level IR, MIR: a flat control-flow graph where every allocation names its arena and every region entry and exit is an explicit statement. The rules would then be written once.

The migration, in one picture

The RFC moves one pass at a time and keeps the old code until the new code is proven equal. M3 is the proof step.

2. Intuition

Imagine moving house with a list of where every box goes. Before throwing away the old list, you make the movers produce a second list from what they actually did, and compare the two. Any disagreement is a bug in the new process, found while the old list still exists. That is shadow mode: the new path runs next to the old one and changes nothing.

A toy example

fun make(): A {
    val a = A(P(3))      // object with a nested payload
    return a
}
Old: memory::plan
A → Dynamic, Program
MIR: ArenaCreateDynamic for node A,
Alloc A in Fresh(..)
→ Dynamic, Program
⇒
equal ✔
Key detail. The payload P(3) is also allocated inside that fresh arena, but it did not create it. My first version called it Dynamic too, and the test caught it on return_value_if_local_object.bork. An allocation is dynamic only if its own node created the arena.

Events as a sorted multiset

For one function, schedule() yields e.g. Push 0, Push 3, Reset 3, Pop 3, Pop 0. From MIR we collect one Push and one Pop for every RegionEnter, and one Reset per RegionReset, each tagged with the region's report id. Both sides are sorted and compared, so only which events happen is checked, not their interleaving.

3. The code

a) RegionInfo.arena

MIR regions only had their own numbering. Each now remembers the ArenaNode::id of the report region it came from (src/mir/body.rs, set in src/mir/build/mod.rs). This is the join key between the two worlds, and #218 will need it. It is not printed, so MIR goldens are unchanged.

b) src/mir/shadow.rs (new)

FunctionDoes
derive_planclass and “program-lived” flag per object or enum allocation
derive_eventssorted push/reset/pop events of one body
compareplan and codegen_push flags vs MIR, both directions; checks body count equals root count. No LLVM needed
compare_allcompare plus per-function events vs schedule() (needs codegen feature)

c) The switch: BORK_MIR_SHADOW

BORK_MIR_SHADOW=1 bork build prog.bork

Runs compare_all after the gate in codegen/mod.rs. A mismatch panics with the function, the arena id and expected versus derived. If MIR cannot be built it says so on stderr instead of passing silently.

d) Tests

  • tests/mir_schedule.rs: full per-function comparison over programs/{build,check} (was: counts over build).
  • tests/mir_shadow.rs (no LLVM): plan and flags over the corpus; every frozen line of tests/golden/memory_plan.txt for programs/build reappears in the MIR-derived plan; and the set of skipped programs is pinned to exactly check/methods/trailing_closure.bork.

4. What the check does not prove

Be careful about what “equal” means here:

CheckStrength
Plan vs MIRround trip the builder reads memory_plan to choose arenas, so this confirms faithful lowering
Push flags vs MIRround trip the builder reads codegen_push
Events vs schedule()independent schedule() walks the HIR on its own
Known gaps. Pops are synthesized one per entered region, so exit placement on early return/break is unchecked (needs path analysis, #217/#218). The golden check ignores the class name (mono renames Option to Option<i32>) and the number in LexicalScope(n), and covers programs/build only because mono keeps just code reachable from main.
