# RFC 0006: A mid-level IR (MIR) between monomorphized HIR and LLVM, introduced incrementally (TS-P7-01, issue #65)

- **Status:** Proposed
- **Date:** 2026-11-04
- **Issue:** #65 (Phase 7: #65 RFC, #66 MIR core + layout, #67 LLVM lowering from MIR)
- **Builds on:** [RFC 0002](0002-ownership-typeck-contract.md), [RFC 0003](0003-borrows-regions-generics.md), [RFC 0004](0004-borrow-carrying-types.md).
- **Number:** 0005 is reserved by RFC 0004 for returned borrows (#202).

Design only. No code changes. The decision to move to MIR is taken (project owner, 2026-11-04); this RFC fixes what the MIR is and the order in which the compiler is moved onto it. Further language work waits for the first usable step (M2).

This revision is based on reading the code in full: `src/escape.rs`, `src/memory.rs`, `src/region_walk.rs`, `src/codegen/regions.rs`, `src/codegen_gate.rs`, `src/sema/walk.rs`, `src/hoist.rs`, `src/sema/{env,policy,region}.rs`, and `src/codegen/llvm/{emit_fn,region_emit,managed_ref,glue,call_abi,arena,expr,match_emit,nullable,presence,text}.rs`, `vec/*`, `array/*`. Read only as signatures or by role: `crates/bork_runtime` bodies (`arena.rs`, `refs.rs`), `codegen/llvm/context.rs`, `sema/walk/branches.rs` beyond `walk_if`, `sema/free_vars.rs`, `sema/analyze.rs`, debug-info code under `codegen/llvm/debug/`. Section 1.2 lists what the second reading added.

### 1.1 What the code shows that shapes the design

1. **Drop is mostly a runtime registration, not a static call.** A `Ref` slot is registered with its arena (`bork_arena_register_ref_drop`), an enum with `Ref` payloads registers tag-switching glue (`bork_arena_register_drop` + `emit_enum_drop`), an `if val` guard registers an observation drop (`bork_arena_register_observation_drop`). Popping or resetting the arena runs them. Only a few values are dropped inline (`drop_ref_value` for temporaries, `Ref` equality, the source of an `if val`). So a MIR "elaborated `Drop(place)` on every path" model does not describe Bork. The MIR must model **arena registrations** as first-class operations (section 3.4).
2. **Arenas are values.** Allocation target is chosen at emit time by `alloc_sink` (a save/restore stack), `Slot.home_arena`, `result_sink` (hidden parameter), the caller's parent arena (hidden parameter), or a freshly created dynamic arena for `ArenaClass::Dynamic` objects (`arena_create_dynamic`, `register_strong_root`, parented to the root for `LifetimeDomain::Program`). Functions have a hidden ABI (`CallAbi`: `Main` 0, `Callee` 1, `OwningReturn` 2 hidden pointers). MIR has to carry arena operands, not only region ids.
3. **Strong/weak `Ref` handles have their own runtime protocol** (`ref_create_out`, `ref_clone_out`, `ref_move_out`, `ref_store_take`, `ref_rehome_out`, `ref_drop_value`, `observe_ref`, count lease). That is the actual set of ownership ops on `Ref`.
4. **Values are copied between arenas at boundaries** (`materialize_owned_value`: strings, arrays, `Vec`, nullables copied into the owner's arena; `Ref`s rehomed) when a value leaves an `if val`/`if` arm, is returned into `result_sink`, or stored in a field. This is an implicit rule today; escape and planning have to agree with it by comment.
5. **Sema ownership runs on the AST, not on HIR.** Moves, branch joins and the `ArenaReport` exist before typeck lowers to HIR, and the LSP depends on them for programs that do not fully typecheck. The sema `Ownership` observations feed `region_walk`, `memory.rs` and `escape.rs` only indirectly (through the tree shape). Any plan that moves move-checking onto MIR must say what the LSP does for broken programs (section 3.7).
6. **Control flow is faked inside a structured walk.** Emission creates `dead` blocks to keep the walk in step after `return`/`break`; `unwind_to_depth` and `exit_after_return` keep the region stack consistent; loops use `begin_loop_generation(preheader)` and `latch` resets; `&&`, `||`, `?:` need `short_circuit_logical_operands` to skip walking the RHS. A CFG removes all of this.
7. **Layout is split.** Struct and enum layout lives in `Codegen` (`record_type`, `enum_layouts`, `enum_layout`), sizes come from LLVM `TargetData`; `vec/layout.rs` and `array/layout.rs` hold container headers. Nothing before codegen can ask "how big is this type".
8. **One more reason for the fragile seam**: `region_walk.rs` and `codegen/regions.rs` both implement the label match, and `tests/peel_agreement.rs` guards the peel rule that two modules must share.

Concrete costs: the same rule ("where does a `move`/`promote`/`concat`/constructor result land") is written in `escape.rs`, `memory.rs`, `region_walk` and `alloc_sink` and kept equal by comments; hazards fixed in #62-#64 (arena leak on early return, reborrow in a loop) lived in the gap between analysis and emission; drop/clone choice is unverifiable before LLVM.

### 1.2 Added by the second reading (expression, container, nullable and sema code)

1. **`T?` is an ordinary enum.** `nullable.rs`: `T?` is the prelude `Option<T>` (#54), a tag-and-payload slot **allocated in an arena** for `Some` and for `None` alike (`emit_nullable_some/none` call `build_enum_slot` on the sink arena). Only `Ref<T>?` keeps its own null handle (`ref_handle_type().const_zero()`). An earlier draft of 3.5 said "niche"; that was wrong. MIR treats `T?` as an `Aggregate` of an enum and `Switch` on its tag; `!!`, `?:`, `?.length`, equality and copy are lowering patterns over that, not separate ops.
2. **`move`/`promote` of arena-storage values is a copy.** `emit_ident_value`: for `String`, arrays, `Vec` and nullables a `Move`/`Promote` use copies into the sink arena (`copy_into_arena`, `copy_array_into_arena`, `copy_vec_into_arena`, `emit_nullable_copy`); only `Ref` has real move semantics (`RefMove` -> `bork_ref_move_out`) and clone (`RefCopy`). `copy_vec_into_arena` clones `Ref` elements and allocates a new header; `copy_array_into_arena` deep-copies `String` elements. `escape.rs` and `memory.rs` model exactly this rule.
3. **Expression order and builtins.** Expressions are emitted post-order through an eval stack and `ChildPlan`; `&&`, `||`, `?:` evaluate the RHS lazily. Calls to builtins are matched **by name** (`print`, `println`, `concat`, `strongCount`, `weakCount`, `stringFromUtf8`); other non-user callees and indirect calls are rejected (`indirect calls`); a `float` call argument after the walk is rejected (`float call argument after walk`). Hidden call arguments are `current_arena` and `result_sink`-or-`sink_arena`. MIR needs a `Builtin` callee kind and a named capability for the rejected forms.
4. **Containers.** `Vec<T>` is a pointer to a 32-byte header `{buf, len, cap, arena}` that lives in the owner arena; the header never moves, `buf` grows by `bork_arena_grow` (first capacity 4, then doubling); `push/pop/get/set/len/capacity/clear`; `pop` returns `Option` (a `Ref` is moved out of the slot); `clear` drops `Ref` elements; a `Vec` of `Ref` registers `bork_vec_drop_refs` on its arena. Arrays and strings are `{ptr, len}` descriptors; array element types are limited to primitives, `String` and `Ref` (`array element unit` is rejected). **Slices:** `emit_slice_values` offsets by `lo` and takes the length from the result type; I found no runtime bounds check for `lo`/`hi` there (typeck rejects bad literal bounds only). The RFC keeps the behaviour (`Intrinsic(Slice)`) and flags it for M5c; whether to add a check is a separate decision.
5. **Strong/weak is decided at runtime.** `bork_ref_store_take` and `bork_arena_classify(source, target) -> RefKind` choose the edge kind from the two arenas; the compiler does not emit a static kind. `RefStore` in MIR therefore needs no kind operand. The runtime has both by-value and `_ptr`/`_out` entry points (`bork_ref_*`), which is an LLVM ABI choice, not a MIR distinction.
6. **Debug info is woven into emission.** Every allocation, copy and slot store calls `cx.debug_allocation`, `debug_copy_origin`, `debug_label_slot`, `debug_declaration`, `debug_label_ref_array`, and `object_pointer` calls `debug_check_handle`, all feeding the runtime `DebugRegistry`. This is more than `StorageLive/Dead`: MIR ops that allocate, copy or store into a slot must carry a `DebugLabel { name, ty, declaration span, source }` side field so M5e can reproduce the same registry contents. Step 14 (M5e) is correspondingly larger than "debug scopes".
7. **Sema ownership details.** Binding origins are `Declared | Captured | View`; transfer sinks are `Binding`, `CallArg`, `ManagedRef`; the maybe-moved join is `join_branch_moves` (a name stays moved if any branch that falls through moved it); `loop_move_ban` forbids moving any outer name inside a `for`/`while` **syntactically**. A CFG dataflow gives a more precise answer than the syntactic ban, so moving this rule to MIR would change which programs are accepted. M4d must keep the ban (or change it deliberately, with its own decision). `if val` over an `Option` is typechecked as `when` but ownership-walked as `if val` (`option_if_vals`, `RegionSite::MatchArm` accepts `IfValSome/IfValNone`), which MIR build must reproduce for region shapes.

## 2. Decision

Introduce a **control-flow-graph MIR**, built from the output of `mono::monomorphize` (`Mono { hir, report, memory_plan, instances }`). Ownership operations, arena operands and arena registrations are explicit in it. Region, escape, planning and gate analyses run on MIR. LLVM is emitted from MIR only. Parsing, name resolution, type inference, trait solving, monomorphization and the **sema AST walk** (for the LSP) are unchanged until M4 decides otherwise.

```
parse -> AST -> sema(AST walk, LSP) -> HIR -> typeck -> mono -> [MIR build] -> MIR analyses -> MIR verify -> LLVM
                                                                  |                |
                                                        layout (Bork-side)   escape / planning / regions / gate
```

Rejected alternatives:

- **MIR-lite** (keep the HIR walkers, only add layout and the visitor split from TODO.md). Cheapest, but findings 1-8 stay: rules remain written in several walkers.
- **Typed-HIR with annotations** (stamp sinks and drop flags onto HIR, as `hoist.rs` already does for one case). Structured HIR cannot express early exits out of nested regions, or per-path registration state; `hoist.rs` is the sign that annotation does not scale.

## 3. MIR design

### 3.1 Shape

Per monomorphic function (`Instance`): locals, basic blocks (statements plus one terminator), a region tree, and an ABI record. Every statement and terminator carries a `Span` and the originating `NodeId`.

- **Locals:** `Local(u32)` with a concrete `TyId` and kind (`Arg`, `Var`, `Val`, `Temp`, `Return`, `Hidden`). Hidden locals: `CallerParent` and `ResultSink` for the `CallAbi` of the function.
- **Places:** local plus projections `Field(i)`, `Index(Operand)`, `Deref`, `Variant(i)`, `Some`.
- **Operands:** `Copy(Place)`, `Move(Place)`, `Reborrow(Place)` (a view passed on, 3.10), `Const`.
- **Arena operands (`ArenaRef`):** `Current` (innermost open region), `Region(RegionId)`, `Home(Local)` (the arena a binding lives in, today `Slot.home_arena`), `ResultSink`, `CallerParent`, `ObjectArena(Local)` (the arena inside an object/enum handle), `Fresh(dyn_id)` (result of `ArenaCreateDynamic`). This replaces the dynamic `alloc_sink` save/restore stack with an explicit operand on each allocating op.

#### 3.2.1 `Match` keeps patterns

`Match(Place, arms)` is a terminator, not a chain of tag tests. Each arm is `{ pat: MirPat, bindings: Vec<(Local, Place projection)>, target: Block }`; bindings are **borrows** of the matched value (the arm never owns the payload, the enum's registered drop glue stays the only releaser), except a `Ref` bound by value, which is `RefClone`d into the arm's arena; a bound `unit` payload declares no local (as `bind_pat` does today); `MirPat` mirrors `HirPatKind` (`Wildcard`, `Bind`, `Lit`, `Variant { enum, index, fields }`, `Some`, `None`) on monomorphic types. Arms are tried in source order; the first matching arm binds its locals and jumps to `target`. A `Match` with no matching arm is excluded by the exhaustiveness result from typeck, so the fall-through edge is `Unreachable`.

Today's `when` lowering tests arms in order with no shared decision tree and does not lower `Some`/`None` patterns (`if val` covers `Ref`); `Match` keeps that order and the `Some`/`None` capability gap. Why patterns stay in MIR: they keep spans and diagnostics tied to the source arm (`HirArm`, `RegionSite::MatchArm`), the verifier can check bindings and exhaustiveness on the CFG, and LLVM lowering (`match_emit.rs`) already switches on the enum tag, so M5 translates `Match` there without a decision-tree pass. Each arm is its own region (as `MatchArm` is today); `force_push` for arms that bind an owned `Ref` becomes the rule in 3.3. A later optimization pass may lower `Match` to tag tests; that is out of scope.

Loops become CFG edges: region entered before the header, `RegionReset` on the back edge, `RegionExit` at the exit block. `break`/`continue`/`return` emit the region exits for every region they leave (replacing `unwind_to_depth`, `exit_after_return` and the `dead` block workaround).

### 3.3 Regions are first-class and decided by MIR

A region tree is built **by MIR construction** from HIR block structure. Whether a region needs a real arena (`codegen_push` today, decided by `block_may_allocate_sink` and `force_push` for arms binding owned refs) becomes a MIR analysis: a region pushes iff it contains an `Alloc`/`RegisterDrop`/`ArenaCreateDynamic` aimed at `Current` or at itself, or a presence observation. `peel_blocks`/`compacted_braces` disappear from the codegen side. During migration the existing `ArenaReport` is consumed in shadow mode (M3) to prove equality, then dropped.

### 3.4 Drop and registration model (replaces "drop elaboration")

Bork's drops are arena-scoped, so MIR keeps that model and makes it checkable:

- `RegisterDrop`/`ObservationRegister` are explicit ops in the region that owns the slot. The verifier checks each `Ref`-typed slot and each enum with `Ref` payloads stored into an arena has exactly one registration, that the registration's arena is not shorter-lived than the slot, and that registrations happen before the first use that could fail to unwind.
- Inline drops (`RefDrop` of temporaries, observation release, source of an `if val`) are ordinary ops; the verifier checks each temporary `Ref` value is consumed exactly once (stored, moved, rehomed, dropped).
- Moves out of a `Ref` slot (`RefMoveOut`) clear the slot, so the registered drop sees an empty handle; the verifier tracks this.
- Static drop flags are introduced only where a *maybe-moved* owned local needs conditional inline release; arena-registered values need none because the runtime handles an emptied slot.

The glue choice (`vec_drop_glue`, `enum_drop_glue`) is made by one function over `TyId` in the module #62 introduced, called by MIR build, not by LLVM emission.

### 3.5 Layout

`src/layout.rs` is taken (it normalizes newlines in source), so layout lives in `src/mir/layout.rs`: `Layout { size, align, fields, repr }` per `TyId`, parameterized by `DataLayout { pointer_size, pointer_align }`. It must reproduce what exists now: record fields in declaration order, enum as `i32` tag plus the largest variant payload (`enum_layouts`), `Vec` and array headers (`vec/layout.rs`, `array/layout.rs`), `T?` as the prelude `Option<T>` enum (see 1.2 item 1; **not** a niche), array and string descriptors `{ptr, len}` (16 bytes), `Vec` header `{buf, len, cap, arena}` (32 bytes, align 8), array element strides from `array_elem_layout` (only primitives, `String`, `Ref`), object handle `{arena ptr, object ptr}`, `Ref` handle, observation struct. A test cross-checks every corpus type against LLVM `get_abi_size`/`get_abi_alignment`/`offset_of_element`. After M5 LLVM struct types come from `Layout`.

### 3.6 Verifier

`mir::verify(&Body) -> Vec<Diagnostic>` runs after build and after every analysis in debug builds and tests:

- every block ends in one terminator; targets exist; locals typed; op operand types agree;
- `RegionEnter/Exit` nest on every path including `return`/`break`/`continue`;
- initialization and move: no read of a moved or uninitialized place;
- arena operands: an `Alloc`/`Promote`/`CopyInto` destination arena encloses the lifetime of the stored value (the property `escape.rs` and `memory.rs` check separately today);
- registration rules from 3.4; temporaries consumed once;
- hidden ABI locals only used in functions whose `CallAbi` provides them.

A verifier failure is an internal compiler error.

### 3.7 Analyses that move onto MIR

| Analysis | From | Notes |
|---|---|---|
| escape / region depth (`String`, objects stored in returned or outer constructs, loop-local objects) | `escape.rs` | depth ints become the arena-lifetime check on `Alloc`/`Promote`/`CopyInto`/field stores; `value_tails`/`holds_object` from `hoist.rs` become MIR-level facts |
| hoisting | `hoist.rs` | an MIR pass choosing the `ArenaRef` of an `Alloc`; the `alloc_in_binding` HIR annotation is removed |
| allocation planning (`Lexical`/`Dynamic`, `Program`/`LexicalScope`) | `memory.rs` | provenance sets become dataflow over `Alloc` results and `RefStore`; call conservatism is kept first; per-function escape summaries are possible afterwards (out of scope here) |
| region schedule and push decision | `codegen/regions.rs`, `region_walk` | disappears (3.3) |
| use-after-move, branch joins | `sema/walk.rs`, `env.rs`, `walk/branches.rs` | **decision needed (M4)**: sema runs on the AST and serves the LSP on partially broken programs. MIR can only be built from programs that typecheck. Proposal: keep the sema AST walk for the LSP as the "fast front check" and remove only what MIR provably covers, i.e. the passes that run *after* HIR (`escape.rs`, `memory.rs`, gate, schedule). Moving the AST move-checker is a separate decision at the end of M4 with its own RFC amendment |
| borrow conflicts (RFC 0003 D3, RFC 0004 borrow sets) | `check_aliased_borrows`, sema | on MIR, conflicts between two live `Borrow`s of one place; closes the hole RFC 0003 sec 5 names (`val b = &a; f(&rw a, &b)`) |
| capability gate | `codegen_gate.rs` | see 3.8 |

User-facing diagnostics keep span and wording; the check_fail corpus compares exact positions (#64), which is the acceptance bar for each analysis moved.

### 3.8 Gate

`codegen_gate.rs` lists rejected shapes by hand (trailing closures, `when` over `Ref`, `Some`/`None` patterns in `when`, unsupported binary operators, field access other than `.length`, moves of enums/records/`Ref` arrays). After M5 the gate is **capability-driven**: MIR build or lowering returns `Unsupported(capability)` for a construct it cannot emit, and `bork check` asks the same function without LLVM (a `Capabilities` table in `src/mir`, seeded from the 3.10 table). One source of truth removes the TODO.md sync test ("every `check()`-ok sample either passes the gate or is listed").

### 3.9 Printing and tooling

Debug labels (1.2 item 6) are printed with their op in `--emit-mir`, so goldens cover them.

`bork build --emit-mir` prints a stable textual form; golden files `tests/golden/mir/*.txt` are the main regression tool for M2-M4. `tools/bork-debug` gets generic-instance names from `Instance { name, origin, args }`, which #67 requires.

### 3.10 Not covered by the design above (decided in step 2, MIR-D, #220)

- **Closures (decided).** Sema opens a region for each closure; HIR keeps only `has_trailing_closure` (`hir/mod.rs`) and `codegen_gate` rejects trailing closures. No `programs/build` program uses one and the emitter has no lowering. MIR build returns `Unsupported(closure)`; no capture model in this RFC. A later RFC must keep the closure body in HIR, add a `Closure` aggregate (captured places as operands) and region rules for captures.
- **Gate gaps (decided).** Each row is "supported" (MIR build lowers it) or a named capability that `Capabilities` (3.8) rejects. Step 14 (M5e) and step 15 (M6) may not claim "no per-shape reject list" until every remaining row is a named capability.

  | Shape | Decision | Capability |
  |---|---|---|
  | Binary operators | Supported. Every `ast::BinOp` is accepted today; the gate's reject branch is dead. A new operator is rejected until MIR build lowers it. | none |
  | `when` over `Ref`, Some-first then None-second | Supported as `Switch` on `Observe` (today's `PresenceMatch`) | none |
  | `when` over `Ref`, any other arm order (general `Match`) | Rejected | `match-ref` |
  | `Some`/`None` patterns in `when` | Rejected; `MirPat::Some/None` exist for `Match` on nullables only once the capability is lifted | `pat-presence` |
  | `move` of enum, record or `Ref`-array | Rejected: the payload would still point into the source arena; needs a deep-copy rule | `move-aggregate` |
  | Field access other than `.length` | Rejected (unreachable today; class fields use `ObjectField`) | `field-access` |
  | `?.` on an enum field (in the gate, missing from the old list) | Rejected | `safe-field-enum` |
  | Indirect call, non-builtin unknown callee | Rejected | `indirect-call` |
  | `float` call argument | Supported: MIR operands are typed, so the coercion is explicit at build time (today an emitter-only error) | none |
  | Array element `unit` | Rejected | `unit-elem` |
  | Bound `unit` payload read in a `when` arm | Rejected (3.2.1: no local is declared) | `unit-payload-bind` |

  Corpus check (after #229): every gate-reject program maps to a row. `build_fail/methods/trailing_closure` -> `closure`; `option/safe_field_of_enum` -> `safe-field-enum`; `option/move_nullable_enum` -> `move-aggregate` (enum); `enums/return_move_object` and `generics/promote_class_object` -> `move-aggregate` (class object); `tests/build.rs` covers `move-aggregate` (enum, class) and `pat-presence`/`match-ref` (`when` over `Ref` with `Some`/`None`). The other `build_fail` programs (`text/*`, `escape_inner_return_string`) are escape diagnostics, not gate rejects. No `build_fail` or `tests/` case exists for `Ref`-array move, `field-access`, `indirect-call`, `unit-elem` or `unit-payload-bind`; M5 adds one test per capability.
  No new rows in the 3.2 op table: every "supported" row uses `Binary`, `Switch`, `Observe`, `Cast`. Emitter-only errors (indirect call, `float` argument, `unit` element and payload) get a gate check in M5 so `bork check` and build agree.
- **Forward compatibility (decided).** Returned borrows (#202) and borrow-carrying view types (RFC 0004) fit `Borrow(Place, Place, Shared or Rw)` with a **borrow set** per local (set of owner places) computed as a verifier dataflow fact; no new op. Gaps and fixes:
  1. Derived sets: `Aggregate` of a view, `Use`, and `Match` payload bindings propagate the owners' sets (RFC 0004 3.2, 3.7).
  2. Calls: `Call` gets `ret_borrows: Vec<arg index>`, so the result's set is the union of those arguments' sets (the #202 return case). Empty for every call today.
  3. Liveness: RFC 0004 locks owners by name until region end. MIR keeps that rule for parity; liveness-based precision is a later option.
  4. Region end: the verifier checks no view outlives its owner at `RegionExit`.
  5. Reborrow: passing a view to a call is a `Reborrow(Place)` operand, not `Copy`/`Move`.
  6. A view with an `&rw` field is non-copyable: only `Move`, enforced by the verifier.
  Additions are one `Call` annotation, one operand kind and one verifier fact.
- **Sema AST move-checker** stays for the LSP (3.7); step 9 records what stays duplicated.
- **Runtime.** `crates/bork_runtime` is unchanged; any change to its ABI is a separate RFC.
- **Tooling and docs.** `bork-debug`, `docs/memory-model.md`, `docs/memory-region-visitor.md`, `tests/peel_agreement.rs`: step 16 (M7).

## 4. Module layout

```
src/mir/
  mod.rs        Body, Block, Statement, Terminator, Place, Operand, Rvalue, ArenaRef
  build.rs      Mono.hir -> Body (expression lowering, regions, registrations)
  layout.rs     DataLayout, Layout per TyId
  verify.rs     verifier
  analysis/     escape.rs, plan.rs (memory), hoist.rs, borrows.rs, regions.rs
  print.rs      textual dump for --emit-mir and goldens
  capability.rs what the LLVM lowering supports (replaces codegen_gate)
src/codegen/llvm/lower.rs   MIR -> LLVM (from M5)
```

The runtime ABI (`crates/bork_runtime`: `ArenaState`, `RefHandle`, `RefObservation`, `DropFn`, ~2.7k lines) does not change in this RFC; MIR ops map to its functions one to one, which is why the Ref protocol ops are explicit.

## 5. Invariants

- **INV-MIR-1:** MIR is built only from monomorphic HIR that passed typeck and sema; no `Param` types.
- **INV-MIR-2:** every allocating op names its arena operand; no implicit "current sink".
- **INV-MIR-3:** every `Ref` slot and `Ref`-carrying enum stored into an arena has exactly one registration; every temporary `Ref` value is consumed exactly once.
- **INV-MIR-4:** region operations nest on every CFG path.
- **INV-MIR-5:** the verifier passes after build and after each analysis on the whole corpus (`programs/**`).
- **INV-MIR-6:** a program that `check()`s and passes the gate never fails MIR build; failures are internal errors.

## 7. Risks

- **Runtime protocol fidelity.** Registrations, observation lifetimes and `Ref` rehoming are subtle (see `materialize_owned_value`, `emit_ref_count` lease). MIR lowering must emit the same runtime call sequences; the first M5 milestone for `Ref` code compares emitted LLVM call sequences for the corpus before enabling it.
- **LSP on broken code.** MIR needs typed, error-free HIR; the AST walk stays for the LSP (3.7).
- **Compile-time and runtime cost.** CFG plus dataflow per instance. M2 measures `bork check`/`build` time on the corpus; budget "no more than 1.5x the pre-MIR `build` time on the quicksort corpus", and emitted-code performance must not regress (benchmark in M6, per #67).
- **Diagnostic regressions.** Spans and `NodeId` on every op; exact-position check_fail tests (#64) before each analysis switches.
- **Two sources of truth during M3-M5.** Shadow equality asserts fail CI; each deleted pass is removed in the same PR as its switch-over.
- **Scope creep.** MIR optimizations and interprocedural escape summaries are out of scope; threads are out of scope.
